From a Slack read to a firewall rule

Fifteen DeepSeek Harness plugins carry one poisoned message from the MCP bridge to an enforceable indicator. Point A is the tool result arriving in the session. Point B is the moment a firewall, an EDR agent or a secret vault can act on it. Everything in indigo is new; everything else already ships in dsh 0.1.1-rc.2.

The sixteen messages

Steps 1–5 are ingestion and scoring. Steps 6–10 are the post attempt and the denial. Steps 11–13 assemble the indicator. Steps 14–16 cross the harness boundary into controls that can actually stop a packet.

  1. 1Returns the Slack message content to [MCP/stdio]Slack workspace → dsh-mcp-client
  2. 2Hands the tool result todsh-mcp-client → dsh-agent-loop
  3. 3Appends tool/result to [durable event]dsh-agent-loop → dsh-session
  4. 4Projects and deep-copies the record fordsh-session → dsh-session-query
  5. 5Hands the redacted copy to [sessionTelemetry/record]dsh-session-query → dsh-session-telemetry
  6. 6Requests slack post_message throughdsh-agent-loop → dsh-tools
  7. 7Finds no approval policy that matches [dsh-user-approval]dsh-user-approval · dsh-permission-presets
  8. 8Runs the monotonic guard in [ctx.tools.guard]dsh-tools → dsh-mcp-guard
  9. 9Denies the url carrying the tagged secret todsh-mcp-guard → dsh-tools
  10. 10Records the denial indsh-tools → dsh-session
  11. 11Reads the read-then-post window fromdsh-invariants → dsh-session-query
  12. 12Fails the chain invariant and reports todsh-invariants → dsh-session-telemetry-otel
  13. 13Adds the injection score todsh-session-telemetry → dsh-session-telemetry-otel
  14. 14Emits the indicator record to [OTLP/HTTP]dsh-session-telemetry-otel → OTel collector
  15. 15Routes the host and canary hash toOTel collector → firewall / EDR / vault
  16. 16Exports the evidence bundle to [download]dsh-session-query → firewall / EDR / vault

Where the boundary really sits

The harness never blocks a packet, and nothing in it can. dsh-sandbox-policy confines writes to the workspace — not reads, not network — and the fetch that completes the theft is made by Slack's own servers, on infrastructure no local control can see. So the deliverable is not a network control. It is a signal precise enough that an existing network control can act on it: a destination host, a canary hash, a session id and a severity, emitted over OTLP at step 14.

The harness proves intent at the API layer. The wire proves delivery. The canary hash is the join.
